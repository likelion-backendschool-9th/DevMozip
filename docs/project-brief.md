# DevMozip — 프로젝트 초기 구성 및 기획 발표용 프론트엔드 개발 요청

## 0. 작업 목적 및 최우선 지시사항

AI 기반 개발자 매칭 및 정보 공유 SNS 플랫폼인 **DevMozip(데브모집)**을 개발하려고 해.

현재 단계는 실제 서비스를 배포하거나 백엔드 비즈니스 로직을 개발하는 단계가 아니라, **기획 발표를 위한 React 기반 프론트엔드 프로토타입을 제작하는 단계**야.

따라서 다음 사항을 최우선으로 지켜 줘.

1. 프론트엔드의 전체 페이지와 주요 사용자 흐름을 구현해 줘.
2. 주요 버튼, 탭, 검색, 필터, 모달, 폼, 페이지 이동이 실제로 동작해야 해.
3. 모든 데이터는 Mock 데이터를 사용해 줘.
4. 백엔드는 Spring Boot 프로젝트의 기본 실행 환경과 폴더 구조만 생성해 줘.
5. 백엔드 Controller, Service, Repository, DTO, Entity 및 실제 REST API는 아직 구현하지 마.
6. 데이터베이스, 인증 서버, AI API, 결제 API는 연결하지 마.
7. 향후 백엔드 개발 시 Mock 데이터만 실제 API로 교체하기 편하도록 구성해 줘.
8. 기존 파일을 확인하지 않고 임의로 삭제하거나 덮어쓰지 마.
9. UI는 단순한 와이어프레임이 아니라 **기획 발표에 사용할 수 있는 완성도 높은 PC 웹 프로토타입**으로 만들어 줘.

### [요청사항]

1. 먼저 현재 작업 디렉터리와 파일 구조를 확인해 줘.
2. 참고 GitHub 저장소에 접근할 수 있는지 확인해 줘.

4. 특히 다음 사항을 확인해 줘.
   - frontend / backend 분리 방식
   - React 프로젝트 구조
   - pages, components, services 등 폴더 관리 방식
   - 기능별 파일 분리 방식
   - 라우팅 구성
   - API 호출 관리 방식
   - 공통 컴포넌트 구성
   - CSS 관리 방식
   - Spring Boot 패키지 구성
   - Controller / Service / Repository 분리 방식
   - DTO의 request / response 분리 방식

6. 기존 프로젝트의 카페 관련 기능이나 디자인은 복사하지 마.
7. 참고 저장소에 접근할 수 없다면 접근 불가 사실을 알려주고, 임의로 기존 구조를 추측하지 마. 대신 아래에 명시한 기본 구조를 사용해 줘.

참고 프로젝트의 **폴더 관리 및 코드 구성 방식**을 참고하는 것이 목적이야. 디자인과 기능은 DevMozip에 맞게 새로 구현해야 해.

# 2. 프로젝트 기획

## [서비스 개요]

- 프로젝트명: DevMozip
- 한글명: 데브모집
- 서비스 유형: AI 기반 개발자 매칭 및 정보 공유 SNS
- 주요 사용자: 개발자, 사이드 프로젝트 참여 희망자, 프로젝트 모집자
- 핵심 목적: 개발자 탐색, AI 기반 팀원 추천, 프로젝트 모집, 협업 경험 및 신뢰도 관리

DevMozip은 개발자들이 기술 정보를 공유하고, 서로 팔로우하며, 프로젝트에 필요한 팀원을 모집하거나 AI 추천을 통해 적합한 개발자를 찾을 수 있는 서비스야.

SNS와 프로젝트 모집 플랫폼을 결합하고, 실제 협업 이력과 평가를 사용자 프로필에 반영하는 것이 특징이야.

## [핵심 기능]

1. AI 개발자 및 유사 프로젝트 추천
2. 개발자 및 프로젝트 통합 검색
3. 프로젝트 모집 및 지원 관리
4. 개발자 SNS
5. 사용자 프로필 및 포트폴리오
6. 프로젝트 활동 이력
7. 협업 리뷰 및 신뢰 온도
8. 팔로우
9. 1:1 메신저 및 프로젝트 단체 채팅
10. 알림
11. 프리미엄 구독
12. 관리자 페이지

# 3. 기술 스택

## 3.1 프론트엔드

다음 기술을 사용해 줘.

- React
- TypeScript
- Vite
- React Router
- Axios
- CSS

필요하다면 Lucide React 같은 가벼운 아이콘 라이브러리를 사용해도 좋아.

기존 참고 프로젝트에서 사용한 프론트엔드 구조와 기술이 현재 요구사항에 적합하다면 최대한 참고해 줘.

불필요하게 많은 라이브러리를 추가하지 마.

## 3.2 백엔드

- Java 21
- Spring Boot (Java 21 호환 최신 안정 버전)
- Gradle
- Spring Web
- 프로젝트명: backend
- Group: com.devmozip
- Package: com.devmozip.backend

현재는 백엔드 프로젝트를 생성하는 단계이므로 Spring Web 외의 의존성은 최소화해 줘.

다음 의존성은 아직 추가하지 마.

- Spring Data JPA
- Lombok
- Spring Security
- JWT
- OAuth2 Client
- PostgreSQL Driver
- Redis
- WebSocket
- 결제 및 AI 관련 SDK

Gradle Wrapper를 포함해 줘.

# 6. 프론트엔드 페이지 및 기능 구현

## 6.1 메인 페이지

### AI 추천 영역

프로젝트에 대한 자연어 설명을 입력할 수 있는 영역을 만들어 줘.

- 프로젝트 설명 입력
- 부족한 정보에 대한 추가 질문 UI
- 관심 분야 및 기술 스택 입력
- AI 추천 실행
- 추천 개발자 표시
- 유사 프로젝트 추천
- 매칭 적합도 퍼센트
- 프리미엄 전용 상세 추천 이유

실제 Gemini API를 호출하지 말고 Mock 추천 로직을 사용해 줘.

사용자가 입력한 기술 스택과 관심 분야에 따라 미리 준비된 데이터에서 결과가 달라지도록 구현해 줘.

추천 점수는 데모용 추정 점수이며 실제 AI 분석 결과가 아님을 구분해 줘.

### 프로젝트 모집 영역

- 최신 모집 공고
- 인기 모집 공고
- 마감 임박 모집 공고
- 프로젝트 상세 이동
- 프로젝트 더보기

### SNS 영역

메인 페이지의 SNS는 반드시 **가로 슬라이드 형태**로 구현해 줘.

- 추천 / 팔로잉
- 정보 / 피드백 / 홍보 / 자유
- 게시글 카드
- 좋아요 / 댓글 / 북마크
- 작성자 프로필 이동
- 전체 피드 더보기

### 프로젝트 홍보 갤러리

Figma Community처럼 프로젝트 결과물을 탐색하는 갤러리는 추후 기능이야.

현재는 별도 게시판을 만들지 말고 향후 추가 예정 기능으로 문서에 기록해 줘.

## 6.3 사용자 프로필

프로필은 반드시 다음 구조로 구현해 줘.

**상단 공통 프로필 정보 + 하단 5개 가로 탭**

프로필 정보를 왼쪽에 고정한 별도 패널 구조로 만들지 마.

### 상단 프로필

- 배너
- 프로필 사진
- 닉네임 및 아이디
- 개발 직군
- 경력
- 한 줄 소개
- 가입일
- 외부 링크
- 연락 가능 시간
- 팔로워 / 팔로잉
- 협업 가능 여부
- 신뢰 온도 및 별 색상
- 프로필 수정 / 팔로우 / 쪽지

상단 프로필은 탭을 변경해도 유지해야 해.

### 탭 1. 소개

- 상세 자기소개
- 관심 개발 분야
- 기술 스택
- GitHub / 블로그 링크
- 프로필 편집

HTML 형식의 소개를 향후 지원할 예정이지만, 현재 프로토타입에서는 안전한 서식 표현만 사용하고 임의 HTML을 직접 삽입하지 마.

### 탭 2. 포트폴리오

- 포트폴리오 등록
- 수정 / 삭제
- 프로젝트명
- 한 줄 소개
- 개발 기간
- 담당 역할
- 기술 스택

프리미엄 상세 정보:

- 프로젝트 상세 설명
- 주요 구현 기능
- 문제 해결 경험
- 개발 과정 및 결과물
- AI 포트폴리오 피드백

무료 / 프리미엄 권한에 따라 열람 가능한 내용을 구분해 줘.

### 탭 3. 내 글

페이스북처럼 **세로 리스트 형태**로 구현해 줘.

- 직접 작성한 글
- 퍼간 글
- 원본 작성자 표시
- 좋아요
- 댓글
- 퍼가기
- 게시글 수정 / 삭제
- 내 글 숨김

퍼간 글은 원본 게시글과 연결되어야 해.

### 탭 4. 활동

DevMozip을 통해 모집하거나 참여한 프로젝트 이력만 표시해 줘.

- 프로젝트명
- 참여 기간
- 담당 역할
- 모집 중
- 모집 완료
- 프로젝트 진행 중
- 프로젝트 종료

프로젝트 클릭 시 실제 Mock 프로젝트 상세 페이지로 이동해야 해.

일반 SNS 활동이나 로그인 기록을 활동 탭에 넣지 마.

### 탭 5. 리뷰

- 실제 협업자만 리뷰 작성 가능
- 프로젝트 종료 후 리뷰 가능 기간 안내
- 별점 필수
- 사전 정의된 긍정 키워드 선택은 선택사항
- 키워드별 선택 횟수
- 키워드별 비율
- 원형 버블 차트
- 신뢰 온도
- 신뢰 온도에 따른 별 색상

신뢰 온도 초기값은 **36.5도**야.

별점에 따라 신뢰 온도가 변화하는 데모 기능을 구현해 줘.

신뢰 온도 계산식은 확정되지 않았으므로 임시 규칙을 사용하고 문서에 표시해 줘.

### [구현 규칙]

1. Mock 데이터는 별도 파일에서 관리해 줘.
2. UI 컴포넌트에 데이터를 직접 하드코딩하지 마.

4. 변경된 데이터는 관련 화면에 일관되게 반영해 줘.
5. 가능하면 localStorage를 이용해 새로고침 후에도 상태를 유지해 줘.
6. 발표용 초기화 버튼을 제공해 줘.
7. Mock 데이터와 실제 API 호출 코드를 교체하기 편하게 구성해 줘.
8. Mock Service는 비동기 호출 형태로 구성해도 좋아.
9. Mock 데이터를 실제 서버 데이터인 것처럼 설명하지 마.
