# 프로젝트 지원 포트폴리오 연결

## 범위

- `feat/48-project-portfolio-link` 작업 디렉터리에서 구현했다. 최신 develop a04608f를 포함한 포트폴리오 CRUD PR #105(7ae37e0)를 기반으로 하며, 해당 선행 코드가 필요하다.
- 기존 프로젝트 지원 API·JWT 신원·최대 3개·재지원 금지·프리미엄 상세 열람 정책과 Mock 시연은 유지한다.
- 프로젝트 지원은 작성자가 ACTIVE인 본인 공개(PUBLIC) 포트폴리오만 받는다. PRIVATE·다른 사람·없는 ID는 거절한다. 사용자는 공개 여부를 선택해 새 포트폴리오를 등록할 수 있다.

## 제출 후 정책

| 항목 | 처리 |
|---|---|
| 제출 전 | 기존 등록·수정·삭제 가능 |
| 제출 성공 | 원본 수정·삭제 409, 상세 canEdit=false / submitted=true |
| 지원 취소·거절 | 제출 이력이 남으므로 계속 수정·삭제 불가 |
| 다른 프로젝트 지원 | 같은 공개 포트폴리오를 다시 선택 가능 |
| 동시 제출·수정 | 같은 포트폴리오 행 잠금으로 직렬 처리 |
| 제출 실패 | 연결 행이 저장되지 않아 수정 제한이 생기지 않음 |

개별 수정 화면 직접 접속과 PUT 호출도 서버에서 차단한다. 상세 화면에서는 수정·삭제 대신 제출 안내를 표시한다. 다른 사람에게는 제출 여부를 공개하지 않는다. 별도 스냅샷은 저장하지 않으므로 DB 직접 수정이나 향후 별도 쓰기 경로도 이 정책을 지켜야 한다. 이미지 파일 자체 보존은 현재 범위가 아니며 외부 이미지 URL의 내용 변경까지 보장하지 않는다.

## DB

`docs/sql/project-portfolio-reference.sql`은 기존 연결 테이블에 `portfolio_id → portfolios.id` FK(즉시 검사, ON DELETE RESTRICT)와 조회 인덱스만 추가한다. 기존 데이터에 누락된 참조가 있으면 전체 적용을 중단한다. FK가 없으면 지원 어댑터는 사용 불가로 응답한다. portfolios·users 컬럼이나 데이터는 변경하지 않는다.

2026-11-09 팀 DB에 적용하고 FK 검증 상태를 확인했다. 적용 전후 portfolios 3행, project_application_portfolios 0행을 유지했다. 테스트 데이터는 격리 PostgreSQL 17 컨테이너에서만 생성했다.
