# 회원 탈퇴

2026-11-10 사용자 확정 정책과 `feat/auth-delete-user` 구현이다. `users`의 참조용 ID·닉네임만 남기고 나머지 개인정보를 NULL로 비운다. `deleted_at`, 신규 테이블, 기존 DDL 변경, 주최자 위임은 사용하지 않는다.

## 보존과 삭제

- 삭제: 이메일·비밀번호 해시·카카오 ID·태그·프로필/배너 사진 참조·외부 링크·자기소개·경력·직군·기술 스택·관심 분야·연락 시간·결제수단 등 `users`의 ID·닉네임 이외 모든 현재 컬럼.
- 양방향 팔로우, 본인의 좋아요·북마크를 삭제하고 채팅 참여를 종료한다. 다른 사람의 메시지와 기존 대화 본문은 유지한다.
- 프로젝트·참여 사실·역할·기간·지원서 본문·제출 포트폴리오 본문·리뷰는 보존한다. 미종료 프로젝트 참여는 LEFT로 바꾸고 지원을 취소하며, 동일 프로젝트 잠금 안에서 종료 동의 정족수를 재계산한다. 완료된 프로젝트 참여·리뷰 기록은 유지한다.
- 제출 포트폴리오 JSON에 복사되어 있던 작성자의 태그·프로필 사진도 NULL로 비운다. 자유 본문·첨부 내용 자체를 분석하거나 임의로 편집하지 않는다.
- 구독은 즉시 CANCELED로 종료하고 거래 기록은 별도 `subscriptions`·`payments`에 유지한다. 참조 대상 회원 행에는 ID·닉네임만 남는다. 남은 이용기간 이월·환불 API 호출은 없다. RENEWING 구독은 결과가 확정될 때까지 탈퇴를 409로 제한한다.
- AI 대화·사용량·추천 등 기존 활동 기록은 보존한다. 새 추천 후보의 기존 ACTIVE 조건으로 탈퇴 회원은 제외된다. 개인정보가 들어 있을 수 있는 사용자 작성 자유 본문까지 자동으로 제거한다는 의미는 아니다.
- 동일 이메일·태그 재가입은 새 ID이며 과거 참여·구독·추천 이력을 연결하지 않는다. 기존 nickname UNIQUE 제약은 유지하므로 보존한 닉네임은 재사용할 수 없다.

## 탈퇴 제한과 인증

- 삭제되지 않은 프로젝트의 주최자이며 상태가 COMPLETED가 아니면 409다. 모집 중 프로젝트는 기존 삭제 정책에 따라 삭제한 후 탈퇴할 수 있고, 나머지는 기존 종료 절차를 마쳐야 한다.
- 회원 ID는 본문에서 받지 않는다. Spring Security의 이메일로 본인 회원을 찾아 행 잠금을 잡는다.
- 비밀번호가 있는 회원은 현재 비밀번호를 확인한다. 카카오가 연결되어 있으면 카카오 인가 코드로 동일 카카오 계정임을 확인한 뒤 연결을 해제한다. 비밀번호 없는 카카오 회원에게 비밀번호 설정을 강요하지 않는다.
- 설정 화면에서 카카오 인증은 `prompt=login`으로 시작한다. OAuth state 검사를 통과한 코드는 현재 액세스 쿠키와 함께 180초짜리 HttpOnly 쿠키에만 보관한다. 콜백 GET은 탈퇴를 실행하지 않으며, 사용자가 안내에 동의하고 마지막 탈퇴 버튼을 눌러야 한다. 기존과 관계없이 재인증하는 공식 계약: [Kakao REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api#request-code).
- 새 액세스·리프레시 JWT는 accountId를 포함하고 현재 이메일의 ID와 대조한다. 이전 형식 JWT는 탈퇴 이메일의 SHA-256 지문을 최대 액세스·리프레시 수명+60초 동안 차단한다. 재가입한 새 ID의 토큰에는 영향을 주지 않는다. 리프레시·비밀번호 재설정 토큰은 개인정보를 비우기 전에 제거한다. 로그인·카카오 토큰 발급·재발급도 같은 회원 행 잠금으로 직렬화하여 탈퇴 이후 과거 인증 결과로 토큰이 다시 저장되는 경합을 막는다.
- 기존 WebSocket은 메시지 전달과 주기 검사에서 이메일·회원 ID 일치를 확인하고 탈퇴 계정 연결을 닫는다.

## API

`DELETE /api/v1/users/me`, Bearer 인증, JSON 요청이다.

```json
{
  "currentPassword": "현재 비밀번호",
  "kakaoCode": "연동된 카카오 계정의 새 인가 코드",
  "confirmed": true
}
```

- 비밀번호가 없는 카카오 회원은 `currentPassword` 생략 가능. 카카오 미연동 회원은 `kakaoCode` 생략 가능.
- 성공 204. 잘못된 비밀번호·확인 미동의·필요한 카카오 코드 누락 400, 인증 없음 401, 사용 불가 계정 403, 미종료 프로젝트 주최·결제 처리 중·다른 카카오 계정 409, 외부 서비스/저장소 오류는 오류 응답이다.
- 설정 화면의 서버 액션이 호출하며 성공한 뒤 인증·카카오 임시 쿠키와 해당 계정의 브라우저 AI 초안을 정리한다. 다른 계정의 초안은 유지한다. 브라우저 저장소 정리가 실패하면 로그인 화면에서 실패를 알린다.

## 외부 정리와 실패 처리

- Redis `withdrawal:cleanup:{userId}`에 빌링키 암호문·직접 관리하는 프로필/배너 파일 이름만 기록한 후 DB 개인정보를 비운다. 작업에는 이메일·비밀번호·카카오 토큰을 저장하지 않는다.
- 커밋된 탈퇴인지 DB에서 확인한 작업만 실행한다. 빌링키는 기존 `BillingKeyCipher`로 복호화하여 PortOne V2의 삭제 API만 호출한다. 이미 삭제된 빌링키는 기존 PortOneClient의 멱등 처리를 따른다.
- 프로필 사진은 다른 회원이 참조하지 않을 때만 삭제한다. 원본/제출 포트폴리오 첨부는 본문 보존 정책에 따라 삭제하지 않는다.
- 커밋 직후 한 번 실행하고, 실패한 부분만 기본 60초 간격으로 재시도한다. Redis의 2분 임대로 중복 실행을 제한하고 성공한 작업은 지운다. DB 롤백 시 동일 작업 ID의 준비 작업만 제거한다.
- 기본/운영 모드는 기존 Redis AOF에 의존한다. `local`·`test`는 메모리 구현이라 재시작 내구성을 제공하지 않는다. PostgreSQL용 JSONB 정리를 사용하므로 H2에서의 탈퇴 동작은 검증 범위가 아니다.
- 카카오는 재인증 토큰을 장기 저장하지 않는다. 연결 해제의 5xx 실패는 현재 요청에서 최대 3회 시도하고 계속 실패하면 DB 탈퇴를 완료하지 않는다. 사용자가 새 카카오 인증으로 다시 시도한다. 카카오 연결 해제와 DB 커밋은 분산 트랜잭션이 아니므로 외부 해제 성공 후 DB 커밋 실패 가능성을 없앴다고 보장하지 않는다.
- Redis 준비 작업 기록/토큰 폐기에 실패하면 개인정보 삭제를 완료하지 않는다. 정리 작업은 회원 행 잠금으로 진행 중인 DB 트랜잭션이 끝날 때까지 기다린다. 프로세스 강제 종료/롤백으로 탈퇴하지 않은 계정의 준비 작업은 동일 작업 ID인지 확인한 뒤 제거한다. 작업 저장소 유실·암호화 키 변경·계속되는 외부 장애는 자동 재시도로 해결할 수 없다.

## 확인한 환경

- Spring Boot 4.1.2, Java 21, Gradle 9.8.2, Spring Data JPA, PostgreSQL 17 설정을 파일에서 재확인했다. `local` 파일의 H2 설정은 변경하지 않았다.
- 기존 DB 점검 스크립트를 통해 실제 팀 DB를 읽기 전용 조회했다. users는 22컬럼이며 ID 이외 컬럼이 NULL 허용이다. 추천·채팅·신고·좋아요·북마크·구독·게시글·포트폴리오·팔로우·사용량의 users FK를 확인했다. 팀 DB 데이터/DDL은 수정하지 않았다.
- 최신 ERD 원본은 제공되지 않아 직접 대조하지 못했다. 원본 Member·Portfolio 엔티티, 패키지 구조, 배포 설정, 타 도메인의 기능 확장은 변경하지 않는다.
