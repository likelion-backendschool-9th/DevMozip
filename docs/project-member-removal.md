# 프로젝트 팀원 강퇴 투표 (#49)

## 동작

프로젝트 채팅 → 멤버 버튼 → 대상 팀원의 강퇴 투표 아이콘 → 사유 선택 → 투표 시작. 생성 전에는 투표 패널을 표시하지 않으며, 생성된 투표는 채팅방의 대화 영역 안에 표시한다.

- 현재 프로젝트·채팅 참여자만 요청·조회·투표할 수 있다. 본인과 주최자는 대상에서 제외한다. 주최자도 다른 팀원과 동일하게 1표다.
- 시작 당시 대상자를 제외한 팀원의 투표권 행을 생성한다. 요청자의 자동 찬성은 없으며, 미투표도 전체 정족수에 포함한다.
- 찬성 > 전체 투표권 / 2이면 가결한다. 사용자당 한 번만 투표하며 변경할 수 없다. 전원 투표 후 과반수가 없으면 부결한다.
- 가결 시 `project_members.status=KICKED`, `left_at=처리 시각`, `end_requested_at=NULL`로 변경하고 같은 트랜잭션에서 채팅 참여를 종료한다. 팀원 행·지원 승인 기록·기존 메시지는 삭제하지 않는다.
- 현재 참여 인원·직군별 인원·종료 동의 정족수는 ACTIVE만 집계한다. 강퇴 후 이미 누른 종료 동의가 새 정족수를 넘으면 종료하며, 리뷰 요청에는 강퇴된 팀원을 포함하지 않는다.
- 주최자 팀원 목록의 이력 조회와 프로필 활동에 ‘강퇴됨’을 표시한다. 강퇴된 승인 지원서는 취소하거나 재승인할 수 없으며 재지원도 불가하다.

## API

| 메서드 | 경로 | 내용 |
|---|---|---|
| POST | `/api/v1/projects/{projectId}/members` | WBS 7.11 투표 요청. `{projectMemberId, reason}` |
| GET | `/api/v1/projects/{projectId}/kick-votes` | 최근 30개 투표·내 투표 상태 |
| POST | `/api/v1/projects/{projectId}/kick-votes/{voteId}/ballots` | `{agree: true 또는 false}` |
| GET | `/api/v1/projects/{projectId}/members?includeInactive=true` | 주최자 전용 전체 참여 이력 |

BFF는 `/api/projects` 하위의 같은 경로를 사용한다. 변경 요청은 기존 세션·동일 출처 검증을 거치며 사용자 ID는 본문에서 받지 않는다. `projectMemberId`는 **project_members.id**다. 채팅 응답의 기존 `id`는 chat_members.id이며 별도 `projectMemberId` 필드를 추가했다. 실제 채팅 제외 서비스에는 **users.id**를 전달한다.

종료된 투표에 대한 재전송은 최신 종료 상태를 반환하고 표를 추가하지 않는다. ACTIVE 투표의 중복 표는 409다. 프로젝트 행 잠금으로 시작·투표·기존 팀원 변경을 직렬화한다. 결과 응답에는 개인별 투표 목록을 노출하지 않는다.

## 기존 테이블 재사용

`member_removal_votes`, `member_removal_ballots`, `project_members`, `chat_members`를 사용한다. 기존 VARCHAR 상태에 KICKED를 추가하므로 이번 변경은 공유 DB의 테이블·컬럼을 변경하지 않는다. 테스트는 별도 PostgreSQL Testcontainers에서 실행한다.

## 임시 정책 및 연동 경계

- 투표 기간 72시간, 기권도 분모에 포함, 프로젝트당 ACTIVE 투표 1개, 진행 중 팀원 변경 시 취소는 임시 정책이다. 사용자의 이번 확정 사항은 **주최자 대상 제외 및 프로젝트 참여에서도 강퇴 처리·이력 보존**이다.
- 만료·팀원 변경은 투표 조회/요청 시 날짜와 현재 명단을 비교한다. 프로젝트 종료 이벤트에서도 투표를 취소한다. 별도 스케줄러는 만들지 않는다. 삭제된 프로젝트는 접근 불가하며 기존 투표 이력은 보존한다.
- 기존 메신저 연결로 `project.members.changed` 신호를 커밋 후 발행한다. 프로젝트 방만 재조회하고 강퇴 대상자의 다른 1:1 채팅 연결은 종료하지 않는다. 연결 유실 시 채팅 및 투표 폴링으로 보완한다.
- 가결 결과는 실시간 토스트로 안내한다. `ProjectMemberRemovalResolved`에 대상·수신자·상태·중복 방지용 eventKey를 제공하지만, **실제 전역 알림함 저장·발송은 알림 담당의 AFTER_COMMIT 소비자 연결이 남아 있다**. 이벤트 발행을 알림함 저장 완료로 간주하지 않는다.
- Mock도 현재 팀원에서 제외하고 passed 투표를 강퇴 이력으로 사용한다. 기존 버전 localStorage 형식을 유지한다.
