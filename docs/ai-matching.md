# AI 추천 기능 명세

기준일: 2026-11-03. 사용자 제공 AI 추천 공통 지침과 현재 저장소 점검을 기준으로 작성했다. 이 문서의 확정 정책은 구현 완료를 뜻하지 않는다. API 계약은 [ai-api-spec.md](ai-api-spec.md), 실제 진행 현황은 [ai-progress.md](ai-progress.md)를 참조한다.

## 기능과 확정 정책

DevMozip은 개발자 매칭·프로젝트 모집·포트폴리오·SNS 서비스다. AI 추천은 프로젝트 조건에 맞는 개발자와 유사 프로젝트를 한 번의 추천 요청에서 함께 생성한다. 추천 결과는 실제 DB 데이터를 기반으로 만들며, 점수는 백엔드가 계산한다. 프론트 Mock의 점수식을 서버 정책으로 확정하지 않는다.

| 구분 | 확정 내용 |
|---|---|
| 자연어 입력 | 사용자의 자연어에서 조건 변경을 추출하고 기존 조건과 병합한다. |
| 직접 조건 선택 | 선택 조건 전체를 PUT으로 교체한다. 부분 변경 API로 취급하지 않는다. |
| 일반 메시지 | 추천 횟수를 차감하지 않는다. |
| 조건 변경 | 직접 선택·자연어 추출 모두 추천 횟수를 차감하지 않는다. |
| 추천 실행 | 사용자가 '조건으로 추천 받기'를 실행하면 개발자·유사 프로젝트 추천을 함께 생성한다. |
| 점수·데이터 | 백엔드 계산, 실제 DB 데이터 기반이다. |
| 신규 결과 생성 | 성공 시에만 추천 1회를 차감한다. |
| 상세 분석 | 프리미엄 사용자가 기존 추천에 추가 분석을 요청하며 추천 횟수는 차감하지 않는다. |

## 입력과 로그인 흐름

1. 비로그인 사용자도 메시지를 입력하고 조건을 선택할 수 있다.
2. 로그인 전에는 DB에 저장하지 않는다. 입력·조건을 임시 보존하는 구체적인 방식과 보존 기간은 TODO다.
3. 추천 버튼을 누르면 로그인 여부를 확인한다. 비로그인 사용자는 로그인 페이지로 이동하도록 안내한다.
4. 실제 추천 실행 API는 로그인 사용자만 호출할 수 있다. 비로그인 호출에는 HTTP 401 Unauthorized를 반환한다.
5. 로그인 후 이전 메시지와 조건이 유지되도록 설계한다. 서버 저장과 실제 추천 실행은 로그인 후 진행한다. 저장 시점·초안 전달 계약·중복 저장 방지는 TODO다.
6. 서버는 Spring Security 인증 정보에서 요청자 ID를 얻는다. 현재 임시 인증의 username을 실제 사용자 DB ID에 연결하는 방법은 TODO다.

공개 입력 UI를 제공한다는 이유로 DB 저장 API를 익명 공개하지 않는다. 비로그인 자연어 처리를 브라우저에서 할지, 별도 비저장 서버 처리로 할지는 미확정이다.

사용자 제공 후속 API 표에 따라 직군·기술 스택·경험 등을 기반으로 적합도를 계산하고 결과를 저장한다. 구체적인 필드 매핑과 가중치는 아직 미확정이다.

| 대상 | 확정된 데이터·처리 | TODO |
|---|---|---|
| 개발자 | 무료는 기본 프로필·공개 기술 스택을 기반으로 추천한다. 직군·기술 스택·경험 등을 적합도에 반영한다. 프리미엄은 상세 포트폴리오 기반 AI 분석을 추가 이용한다. | 비교 필드의 세부 정의, 필수 필터, 가중치, 점수 범위, 정렬·동점 처리, 후보 수, 본인 제외 및 비공개·탈퇴·협업 불가 사용자 처리 |
| 유사 프로젝트 | 동일 추천 요청의 조건으로 실제 DB 프로젝트를 비교해 함께 제공한다. 점수는 백엔드에서 계산한다. | 분야·기술·직군·기간 등 비교 필드, 모집/종료 상태 포함 범위, 가중치, 후보 수, 정렬·접근 가능 범위 |

프론트에는 분야·관심·기술·직군별 인원·경력·기간 등의 Mock 조건과 점수식이 있다. 이는 참고 자료이며 서버 필드·검증 규칙·알고리즘의 확정 근거가 아니다. 자연어 병합 시 삭제/부정 표현, 배열 교체·추가, 충돌 우선순위, 추출 실패 시 동작도 TODO다.

## 무료·프리미엄 및 사용량

| 항목 | 무료 | 프리미엄 |
|---|---|---|
| 추천 근거 | 기본 프로필·공개 기술 스택 | 기본 추천에 상세 포트폴리오 기반 AI 분석 추가 이용 가능 |
| 월 추천 한도 | 15회 | 100회 |
| 기존 추천 추가 상세 분석 | 제공 대상 아님 | 가능, 추천 횟수 차감 없음 |

메시지 전송·조건 변경·실패한 신규 추천은 차감하지 않는다. 개발자·프로젝트 결과를 함께 생성하는 한 요청의 성공에 1회 차감한다. 동시 요청에서도 한도를 지키고, 실패 시 차감하지 않도록 결과 저장과 사용량 갱신의 일관성이 필요하다.

## 데이터와 현재 차이

화면 URL은 `/ai/matching`이며 현재 `frontend/app/ai/matching/page.tsx`와 일치한다. 앞선 문서의 현재 경로 `/matching` 설명은 정정했다. 라우트 변경은 필요하지 않다. 대화 생성/목록/상세/삭제, 메시지, 조건 교체, 추천 생성/조회, 프리미엄 상세 분석, 월별 사용량의 메서드·경로는 [API 명세](ai-api-spec.md)에 반영했다. 상세 분석 경로는 사용자 오타 확인에 따라 `/api/v1/ai/recommendations/{id}/detailed-analysis`로 확정했다. 대화 삭제는 본인 대화만 허용한다.

사용자가 제시한 테이블은 `ai_conversations`, `ai_messages`, `ai_recommendation_requests`, `ai_recommendations`, `ai_usages`다. 사용자 제공 ERD 사진과 users DDL을 확보했다. 실제 AI 테이블·FK·제약조건은 DB에서 검증하지 못했다. 1단계에 필요한 대화·메시지 엔티티와 검토용 DDL 초안만 추가하며, 다른 팀원 소유 사용자·프로젝트·포트폴리오·구독 엔티티는 만들지 않는다.

현재 `frontend/lib/matching/matchingChatService.ts`에는 메시지만 전송해도 조건에 따라 Mock 추천을 생성하고 사용량을 차감하는 분기가 있다. 이번 정책과 차이가 있으며, 이번 문서 작업에서 변경하지 않았다. 기존 API 초안의 `/api/v1/matching/...` 후보는 신규 기준 `/api/v1/ai`와 다르므로 그대로 구현하지 않는다.

## 1단계 추가 확정 정책

- `ai_conversations.type`, `status`는 사용하지 않는다. 한 대화에서 개발자·유사 프로젝트 추천을 함께 제공하며 MVP에는 대화 종료·보관이 없다. 기존 DB에 해당 컬럼이 있다면 제거는 별도 검토·승인 후 수행한다.
- 대화 삭제는 물리 삭제이며 연결된 메시지·추천 요청·추천 결과를 하나의 트랜잭션에서 삭제한다. 추천 요청이 대화뿐 아니라 메시지를 참조하는 FK도 고려한다. 월 사용량은 삭제하거나 복구하지 않는다.
- 1단계 메시지 전송은 사용자 메시지 저장만 한다. 자연어 분석·조건 병합·추가 질문·Gemini·임시 AI 답변·추천 실행·월 한도 계산은 후속 범위다.
- 인증 팀 개발과 분리하기 위해 `CurrentUserProvider`를 사용한다. 개발·테스트 고정 ID는 환경 설정으로 전달하고 기존 users에 실제 존재하는지 확인한다. 실제 인증 어댑터가 없는 운영 환경에서는 AI 요청을 거부한다. 기존 보안 설정은 변경하지 않는다.

## DB 사용 방침 갱신

팀은 H2를 사용하기로 했다. 적용 환경 범위, 메모리/파일 저장 방식, 팀 공통 DDL·초기화 설정은 TODO다. 현재 저장소의 기본 application.yaml/compose는 PostgreSQL이며 H2는 testRuntimeOnly로만 포함되어 있다. 문서 방침 반영과 실제 실행 설정 반영을 구분한다. 이번 갱신은 문서만 변경한다.

현재 1단계 테스트는 H2의 PostgreSQL 호환 모드와 격리 fixture를 사용하며 팀 공통 H2 스키마 검증을 뜻하지 않는다. docs/sql/ai-conversations-proposal.sql은 이전 PostgreSQL 설계 검토용 초안으로 남겨두며 H2 적용용·자동 실행용·승인된 마이그레이션이 아니다. 기존 추천·로그인·차감·삭제 정책은 H2 선택으로 변경되지 않는다.
