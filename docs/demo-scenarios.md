# 발표 시연 순서

## 준비

1. `cd frontend` → `npm ci` → `npm run dev` (Next.js), `http://localhost:5173` 접속. 로그인에 백엔드가 필요하므로 백엔드를 먼저 실행합니다([환경 준비](setup-after-ai.md)). 현재 프론트엔드는 Next.js App Router이며 빌드 후 시연은 `npm run build` → `npm run start`, `http://localhost:4173`입니다.
2. 발표는 PC 브라우저 1440px/배율 100%로 시작합니다. 5차에서는 1920/1440/1280/1024/768/390px, 높이 1000px를 실제 Chromium에서 검사했습니다.
3. 새 격리 브라우저(또는 사이트 데이터 삭제 후)에서 **로그인** → `member@devmozip.demo`로 로그인합니다.
4. 기본 계정: 김하늘(일반), 이서준(프리미엄/Pocket 주최자), 관리자. 이메일 로그인 공통 비밀번호 `Devmozip123!`. 계정 전환은 헤더 **로그아웃** 후 해당 계정으로 다시 로그인합니다.
5. B의 지원 승인 상태를 D가 사용하므로 A→B→C→D→E 사이에는 초기화하지 않습니다.

기본 공고 일정은 2026년입니다. Pocket 마감은 2026-11-02 한국 시각 끝입니다. 마감 후 발표라면 프리미엄 주최자로 먼저 기간을 연장하거나 현재 날짜로 신규 공고를 만들고 B/D의 Pocket 대신 사용하세요. 새 공고에는 주최자 외 모집 인원을 설정하고 일반 계정의 포트폴리오로 지원합니다.

## A. AI 추천 → 개발자 프로필 → 협업 제안

1. 일반 회원으로 메인에서 “React와 TypeScript로 팀의 일정을 관리하는 웹 생산성 프로젝트를 만들고 싶어요.” 입력 → **추천 시작**.
2. `/matching`에서 첫 메시지·추가 질문을 확인합니다. 이때 사용량은 그대로입니다.
3. **프로젝트 조건 설정**에서 분야 웹/모바일 등 복수 선택, 관심 생산성, 기술 React/TypeScript, 직군 프론트엔드 2명/백엔드 1명, 경력 무관, 기간 3개월 → **조건으로 추천 받기**.
4. 개발자/유사 프로젝트·데모 적합도·사용량 1회 감소 확인. 다른 조건으로 재추천하면 점수/순위가 달라집니다.
5. 개발자 카드의 프로필 또는 **협업 제안** → 프로젝트명/10자 이상 제안 → **협업 제안 보내기**. 기존 메신저에 반영됩니다.
6. `/matching`으로 돌아와 “고마워요” 전송 → 추가 차감 없음. 새 대화 작성 후 이전 기록 열기/새로고침으로 메시지와 결과 복원을 확인합니다.

프리미엄 전환 시 같은 입력의 상세 추천 이유를 확인할 수 있습니다. 실제 AI/외부 메시지는 호출하지 않습니다.

## B. 프로젝트 검색 → 상세 → 지원 → 승인 → 프로젝트 채팅

1. 일반 회원 → `/search?target=project` → Pocket 검색 → 상세.
2. **프로젝트 지원하기** → 지원 직군 **백엔드** → 내 포트폴리오 선택 → 10자 이상 멘트 → **지원서 제출**.
3. **로그아웃** → **프리미엄 회원**(이서준)으로 로그인 → **주최자 관리** → 지원서 **지원 승인**.
4. **팀원** 탭에서 김하늘 등록 → **프로젝트 채팅방 열기** → 메시지 전송.
5. 일반 회원으로 전환해 같은 방의 멤버/메시지를 확인합니다. 브라우저 새로고침 후에도 유지됩니다.

지원 취소는 팀원/채팅 접근도 해제합니다. D를 이어갈 때는 승인 상태를 유지하세요. 마감 3일 전 이후 취소 패널티는 임시 예시 안내만 표시하고 실제 온도를 차감하지 않습니다.

## C. SNS 글 → 좋아요 → 댓글 → 퍼가기 → 내 프로필

1. 일반 회원 → `/feed` → **TypeScript로 폼 상태 안전하게 다루기**.
2. 좋아요 → 댓글 입력/등록 → **퍼가기** → **바로 퍼가기** 또는 의견 추가.
3. `/users/demo-user?tab=posts`에서 퍼간 글과 원본 작성자 이유나·원본 연결 확인.
4. 새로고침 후 반응/댓글/퍼가기 유지 확인. 메인 가로 피드도 같은 상태를 사용합니다.

초기 일반 계정은 “React 컴포넌트, 어디까지 분리하시나요?”를 이미 퍼간 상태입니다. 이 글에서는 **퍼가기 관리**가 표시되므로 새로운 퍼가기 시연은 위 TypeScript 글을 사용하세요. **외부 공유**는 URL 복사이며 내 프로필에 글을 추가하지 않습니다.

## D. 프로젝트 종료 → 리뷰 요청 링크 → 전체 평가 → 버블/온도

1. 프리미엄 주최자 → `/my-projects/pocket/manage?tab=settings` → **프로젝트 종료** → 확인. 기본은 채팅 읽기 전용 보관입니다.
2. 일반 회원 → `/notifications` → **협업 리뷰 작성 요청**의 **팀원 리뷰 작성**. 본인에게 발급된 임시 링크가 열립니다.
3. 본인 외 모든 미제출 팀원에게 별점 **5점**, 이서준에게 선택 키워드 **소통이 원활해요** → **전체 제출**.
4. 전체 제출 완료·중복 제출 제한 → 이서준 `/users/demo-premium?tab=reviews`에서 평균/버블/온도 **36.5→37.5°C** 확인.
5. 프로필 리뷰 탭에는 작성 폼이 없습니다. 작성은 프로젝트 요청 알림에서만 가능합니다.

기간 30일과 온도 계산은 임시 정책입니다. 날짜 시뮬레이션 중이면 해당 시각이 작성/만료 기준입니다.

## E. 무료 제한 → 프리미엄 데모 활성화 → 공고 작성

1. 일반 회원 → `/projects/new`에서 작성 제한 안내 → **프리미엄 안내**.
2. **무료로 데모 구독 전환** → 확인. 계정은 김하늘 그대로이며 역할만 프리미엄으로 바뀝니다.
3. PRO 뱃지·추천 월 100회·상세 열람 권한 확인 → `/projects/new`.
4. 제목/소개/목표·기술·기간·모집 직군/인원 작성. 모집 시작=오늘, 마감=7일 후, 개발 시작=8일 후, 종료=60일 후 등 유효한 날짜 사용.
5. **모집 공고 등록** → 상세·목록·주최자 관리·내 활동 반영 확인.
6. 구독 해지는 즉시 무료로 전환하고 공고/사용량은 유지합니다. 표시 가격은 예시이며 결제되지 않습니다.

## 추가 확인

- `/notifications`: 개별 읽음/안 읽음·모두 읽음 → 헤더 개수 변화·새로고침.
- `/`: SNS 다음/이전 슬라이드, 추천/팔로잉·카테고리 변경.

- 프로필: 상단 유지·5개 가로 탭·포트폴리오 CRUD·키보드 좌우 탭 이동.
- 관리자: 관리자 계정으로 로그인 → `/admin` → 회원 검색·경고/정지/해제, 프로젝트 신고 검토, 글 숨김/복원·댓글 삭제, 키워드 관리·AI/온도/구독 현황.
- 관리자 데모에서 정지한 회원은 로그인해도 로그아웃 상태로 표시됩니다. 관리자에서 해제하면 복원됩니다.
- 발표 종료 후 시연 상태를 처음으로 되돌리려면 브라우저 사이트 데이터(localStorage·쿠키)를 삭제합니다. 서버 계정은 바뀌지 않습니다.

## 검증 근거

[최종 브라우저 보고서](artifacts/final-verification/report.json)의 A~E 및 추가 검사 48개가 실제 Chromium에서 통과했습니다. 자동 검증은 별도 격리 브라우저를 사용하므로 발표자의 기존 localStorage를 변경하지 않습니다. 실제 서버/외부 기기 간 통신은 없습니다.

## 1차 수정 추가 시연

1. 일반 회원 → 내 프로필 → 왼쪽 Aside와 5개 탭 확인. 이유나 등 다른 공개 프로필에서는 Aside가 없습니다.
2. TypeScript 글에 좋아요 → Aside의 좋아요한 글 → 날짜/내용 확인 → 상세에서 좋아요 취소 → 목록 제거 확인.
3. 글과 Pocket을 북마크 → 내 북마크함의 게시글/프로젝트 탭 → 원본 이동·해제·새로고침.
4. 개인정보 및 계정 설정 → 데모 비밀번호 `Devmozip123!`와 새 가상 값 입력 → 변경 요청 시 실제 비밀번호 변경은 아직 제공하지 않는다는 안내가 표시됩니다. 실제 로그인 비밀번호는 그대로입니다.
5. 카카오 연동/해제 확인 → 계정별 유지 확인. 프리미엄 계정에서는 가상 카드와 기존 결제 예시를 볼 수 있습니다.
6. 비공개 계정 전환 확인 → 본인 기능 유지 → 다른 계정/비로그인으로 프로필·작성 글 비공개 확인 → 다시 본인 설정에서 공개 전환.
7. 비로그인 → 회원가입(가상 정보·중복 확인·기존 필수 선택값) 입력 검증 확인. 가입 제출 시 실제 회원가입은 아직 제공하지 않는다는 안내가 표시됩니다.
8. 기본 정보/사진 → 복수 직군·기술·관심 분야/기타 분야 → 협업·프로젝트 분야·연락 시간·링크 → 최종 미리보기 → 완료 → Aside가 있는 내 프로필.
9. 중간에 이전/다음, 선택 태그 삭제, 새로고침 초안 복원, 완료 후 닉네임·사진·복수 직군·기타 분야·관심 프로젝트 반영을 확인합니다. 기존 데모 계정은 온보딩을 다시 요구하지 않습니다.

신규 검증 12개와 기존 48개 회귀 결과는 [1차 수정 보고서](changes-account-onboarding.md)에 있습니다.

## 2차 프로젝트 워크스페이스·알림 시연

1. `/my-projects`에서 전체/내 모집/내 참여/지원 중/종료 탭, 역할·주최자·기간·현재 인원 확인.
2. 일반 회원 Pocket 지원 → 지원 중 탭의 참여 정보 → 프리미엄 주최자로 승인 → 일반 계정의 팀원 등록/채팅 연결 확인.
3. 프리미엄 `/my-projects/pocket/manage?tab=settings`, 날짜 시뮬레이션을 **2027-03-04 12:00**으로 적용 → 종료 예정일 경과 알림 확인.
4. 알림 **프로젝트 수정하기** → 기간 연장 모달에서 개발 종료일을 **2027-04-03**으로 연장 → 이전 안내 **처리 완료** 확인.
5. 관리에서 모집 완료 → **프로젝트 시작** 확인 → 날짜를 **2027-04-04 12:00**으로 적용 → 새 종료일 경과 안내의 **프로젝트 종료 처리** → 확인.
6. 일반 회원의 리뷰 요청 링크 진입. **+3일** → 재알림 1회 확인 → 새로고침 후 중복 없음 → 별점 미선택 제출 오류 → 전원 평가/전체 제출.
7. 일반 회원은 추가 **+3일**에도 재알림이 늘지 않습니다. 미제출 프리미엄 계정은 3/6일 재알림 2개를 확인합니다.
8. 종료 시각에서 31일 후로 날짜 적용 → 미제출 링크의 기간 만료·제출 차단·재알림 중단 확인. 완료자의 기존 받은 리뷰는 유지됩니다.
9. 시연 후 **실제 날짜로**를 눌러 시각을 복원합니다. 시연 상태까지 되돌리려면 브라우저 사이트 데이터를 삭제합니다. 다른 시나리오와 섞지 않으려면 별도 격리 브라우저를 사용하세요.

[2차 검증 및 스크린샷](changes-project-workspace.md)에 실제 수행 결과를 정리했습니다.

## 3차 단체 채팅 강퇴 투표·권한 시연

1. 일반 회원으로 모집 목록 또는 내 프로젝트의 공고 작성 버튼 → 프리미엄 안내 모달. **프리미엄 데모 활성화** 후 같은 계정으로 공고를 작성합니다. 관리자에게는 생성 우회 권한이 없습니다.
2. 투표 시연을 위해 격리 브라우저(또는 사이트 데이터 삭제 후)에서 프리미엄 이서준으로 주최자+지원자 1명 규모의 새 공고를 생성합니다. 현재 날짜에 맞는 모집 기간과 일반 회원이 지원 가능한 직군/경력을 설정합니다.
3. 일반 김하늘로 지원 → 이서준으로 승인. 제출 포트폴리오 상세가 열리는지 확인합니다. 구독 해지 시 상세는 잠기며 기존 관리 화면은 임시 유지됩니다. 재활성화 시 상세가 복원됩니다.
4. 단체 채팅에서 김하늘을 대상으로 사유 선택 → 투표 시작. 김하늘로 전환하면 대상자 투표 불가, 이서준으로 찬성하면 유권자 1명 중 1표로 과반수 가결됩니다.
5. 김하늘로 전환 → 방 접근 제한과 결과 알림, 메신저 방 제거, 새로고침 후 제한 유지 확인. 내 프로젝트에서는 참여 이력이 유지됩니다(임시 정책).
6. 절반 미달/기간 만료는 초기 Flowmate에서 김민준 대상 투표를 일반 회원으로 시작하여 찬성합니다. 유권자 2명 중 1표는 과반수가 아닙니다. 같은 계정 재투표는 차단됩니다. 날짜 시뮬레이션 +3일로 만료·강퇴 없음 확인. NPC의 표를 임의로 추가하지 않습니다.
7. 날짜는 **실제 날짜로** 복원합니다. 기록까지 복원하려면 브라우저 사이트 데이터를 삭제합니다.

[3차 실제 검증 보고서](changes-chat-kick.md)에 신규 12개 및 회귀 72개의 근거를 정리했습니다.

- 기타 분야/직군 직접 입력 후 태그 삭제, 직군별 인원, 필수 조건 누락 질문.
- 무료 15회 제한 후 프리미엄 데모 활성화 → 같은 계정 월 100회와 상세 이유.
- 대화 삭제 확인 시 이미 사용한 횟수 유지. 계정 전환 시 각 계정 기록/사용량 분리.
- 월 경계는 한국 시각입니다. 자동 브라우저 검증에서 브라우저 시계를 다음 달로 이동해 새 한도를 검사했습니다. 사용량 초기화용 임의 UI는 추가하지 않았습니다.
- [4차 실제 검사와 변경 파일](changes-matching-chat.md)

## 5차 통합 발표 확인

1. 헤더의 **통합 검색 아이콘** → 개발자/프로젝트 전환 → 검색 결과 → 상세. 헤더에는 입력창이 없습니다.
2. A→B→C→D→E의 기존 순서를 유지합니다. 가입→온보딩→프로필, 좋아요/북마크/설정은 1차 추가 시연, 기간 종료/연장/리뷰는 2차 추가 시연을 사용합니다.
3. 강퇴 투표는 3차 시연처럼 별도 2명 방에서 과반수 가결을 보여주세요. 프로젝트 참여 이력 유지 정책은 임시임을 함께 설명합니다.
4. AI 복수 조건/대화 기록/일반 메시지 미차감/프리미엄 차이는 4차 시연을 사용합니다.
5. 화면을 768px 또는 390px로 줄여 헤더 2행, **개인 계정 메뉴 펼치기**, **대화 기록 펼치기**를 확인합니다. 메뉴를 연 뒤 기존 화면으로 이동할 수 있습니다.
6. 모바일 크기에서도 프로젝트 지원 모달 → 다른 계정으로 로그인해 승인 → 단체 채팅 메시지 전송이 가능합니다. 긴 소개/링크는 줄바꿈하고 카드 수는 자동 조절합니다.
7. 시연 후 필요하면 브라우저 사이트 데이터를 삭제해 초기 상태로 되돌립니다. 서로 다른 PC/브라우저의 저장 상태는 공유되지 않습니다.

## Next.js 마이그레이션 시연 확인

기존 A~E 및 1~5차 추가 흐름을 같은 URL로 사용합니다. 처음 진입할 때 저장소 준비 안내 후 화면이 나타납니다. Next 링크/쿼리로 이동해도 계정·지원·추천·대화 상태가 유지되며 새로고침하면 같은 저장 키에서 복원합니다. 삭제/초기화 시나리오는 격리 브라우저에서 진행하세요. 현재 결과는 [Next.js 보고서](changes-nextjs-migration.md)에 있습니다.
