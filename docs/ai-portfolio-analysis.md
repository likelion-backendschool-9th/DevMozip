## 확정 범위

- 저장된 개발자 추천 결과를 소유한 사용자만 요청한다. 프로젝트 결과는 400이다.
- **현재 DB 역할 PREMIUM/ADMIN이며 현재 유효한 구독 기록이 있어야 한다.** 사용자 추가 답변으로 구독 없는 PREMIUM 데모 계정 허용 제안은 폐기했다. ADMIN도 구독 기록을 우회하지 않는다. 무료 USER/OWNER는 차단한다.
- 추천 요청 당시 conditions와 `_requirements.facts`를 사용한다. 이후 대화 변경은 입력을 바꾸지 않는다. 6A와 동일하게 본인 기술·추론·면제 요구는 평가에서 제외하고 정형 기술·직군·관심 분야를 보완 비교한다.
- 대상 개발자의 현재 ACTIVE·유효 tag와 PUBLIC 포트폴리오만 허용한다. PRIVATE·미확정 visibility·첨부·외부 URL을 읽거나 전송하지 않는다.
- 관련 자료 최대5개를 분석한다. 본문 근거·선택 이유·사용 자료·미확인·협업 전 확인 질문을 제공한다. **큰 가산점·순위 재계산은 후속 범위**이며 이번에는 기존 점수를 유지한다. 상세 생성/조회로 월 추천 사용량을 차감하지 않는다.

## 구독 판정

AI 전용 JDBC Repository가 기존 `subscriptions`를 읽기만 한다. 최신 기록은 starts_at 내림차순, 동률 id 내림차순이다. 유효 구독 하나를 임의 생성하거나 users.role을 갱신하지 않는다.

- 역할: 현재 users.role가 PREMIUM 또는 ADMIN. 오래된 JWT나 브라우저 구독 데모는 근거가 아니다.
- 요청자 ACTIVE/WARNED만 허용, 정지/미확정 상태는 차단.
- 최신 구독 status는 ACTIVE/RENEWING/CANCEL_REQUESTED만 허용. CANCEL_REQUESTED는 즉시 해지와 구분하여 기간 안에서 허용한다.
- DB 공통 시각을 Asia/Seoul LocalDateTime으로 변환하여 `starts_at <= 현재 < current_period_end`를 검사한다. ended_at이 있으면 현재가 그 이전이어야 한다. 시작/종료 시각 NULL·기록 없음·EXPIRED/CANCELED/미확정 상태는 403.
- 구독 테이블/조회 오류는 503이고 역할만으로 우회하지 않는다. 캐시 hit, 생성 직전, 저장 직전, 저장 후 응답 전에도 새 읽기로 검사한다.
- 원본 ERD는 확보하지 못해 문서 전사와 코드·실제 PostgreSQL17.11 메타데이터/상태 CHECK를 비교했다. 기존 구독 담당 서비스의 전역 정책을 변경하지 않으며 판정 기준은 이 AI 상세 API에 한정한다.

## 자료 선택·분석

1. 해당 개발자의 전체 PUBLIC 메타데이터를 ID 커서로 200개씩 읽는다. 최신 일부만 먼저 자르지 않는다.
2. 제목1000/요약3000/역할500/기술3000자까지 HTML 제거·개인정보 패턴 마스킹 후 정규화한다. 조건과 메타데이터의 관련 어휘를 비교한다. 명시 세부 요구의 어휘 일치는 정형 조건보다 4배 비중이며, 관련도 내림차순·동점 ID 오름차순으로 최대5개를 선택한다. 이 수치는 **자료 선택용**이며 추천 점수가 아니다.
3. 관련도0은 선택하지 않는다. 먼저 고른 상위5개에 본문이 없으면 분석에서 제외하고6번째 이하로 다시 채우지 않는다. 관련 자료/본문이 없으면 NO_DATA로 저장하며 Gemini를 호출하지 않는다.
4. 선택한 본문은 자료당6000자까지만 마스킹/HTML 제거 후 모델에 전달한다. 잘린 자료는 응답 truncated=true로 알린다. 첨부/PDF/이미지/OCR·링크 크롤링은 하지 않는다.
5. 요구8개씩 구조화 응답을 요청한다. MET/PARTIAL/MISMATCH/UNKNOWN, 요구ID, 선택된 포트폴리오ID, 필드, 정확한 인용만 받는다. 누락 쌍·가짜 인용은 UNKNOWN이며 인용을 숨긴다. 위조 후보/요구ID·중복·응답 구조 오류는 전체 실패다. 기술 목록·역할로 실제 구현 경험을 입증하지 않는다.
6. 선택 이유와 실제 인용·출처, 미확인/부분 부합의 협업 전 확인 질문을 서버에서 구성한다. 모델 자유 서술이나 점수·순위를 저장하지 않는다. 포트폴리오는 자기서술이며 인용 검증은 성과/실력 진위 인증이 아니다.

선택은 설명 가능한 어휘 비교이며 임베딩/별도 모델 기반 의미 검색이 아니다. 다른 표현의 동의어·요약에 없는 본문 경험은 놓칠 수 있다. 본문6000자 이후도 미분석이다. 이 한계를 숨기지 않으며 다른 자료 수동 선택은 미구현이다.

## API

- `POST /api/v1/ai/recommendations/{id}/detailed-analysis`: 생성/유효 캐시 재사용. id는 **추천 결과 PK**이며 requestId가 아니다. 본문 없음 또는 `{}`만 허용한다. 사용자ID·조건·점수 입력은 받지 않는다.
- `GET /api/v1/ai/recommendations/{id}/detailed-analysis`: 현재 권한/자료 재검증 후 저장 결과·상태만 반환. Gemini를 호출하지 않는다.
- BFF는 동일한 `/api/ai/recommendations/{id}/detailed-analysis`. 기존 HttpOnly 쿠키 인증만 사용하고 POST 동일 출처·빈 JSON·ID·응답 필드/출처를 검증한다. Cache-Control=no-store.

응답: recommendationId/status/cached/generatedAt/portfolios/assessments/questions/notice.

- portfolios: id/title/selectionReason/truncated, 최대5개.
- assessments: requirementId/requirement/status/portfolioId/field/quote. UNKNOWN은 마지막3개가 NULL이다.
- 질문은 미확인/부분 부합 항목에서 최대8개 제공한다.

| 상태 | HTTP | 의미 |
|---|---|---|
| NOT_GENERATED | 200 | 생성 전 GET |
| PENDING | 202 + Retry-After:3 | 다른 요청이 생성 중. 상세 인용 없음 |
| READY | 200 | 생성/재사용된 유효 분석 |
| NO_DATA | 200 | 관련 공개 본문 부족, 모델 미호출 |
| STALE | 200 | 자료/모델·버전 변경 또는 임대 만료, 과거 상세 인용 숨김 |
| FAILED | 200(GET) | 이전 생성 실패. 상세 인용 없음, 명시 POST로 재시도 |

오류는 기존 ErrorResponse: 400 잘못된 ID/본문/프로젝트 대상, 401 미인증, 403 무료·유효 구독 없음/만료, 404 타인 소유 결과·현재 공개 개발자 부재/삭제, 409 생성 중 자료·요청 상태 변경, 429 Gemini 제한, 502 외부/구조화 응답 검증 실패, 503 설정·저장소·중단, 504 시간 초과. 오류의 SQL·자료 원문·키를 BFF로 전달하지 않는다.

## 저장·동시성·실패

- 기존 `ai_recommendations.detailed_reason` TEXT에 version1 JSON을 저장한다. Member/Portfolio 엔티티·테이블·추천 기본 DTO는 변경하지 않는다. 기존 기본 추천 API에는 상세 인용이 섞이지 않는다.
- JSON은 status/token/leaseUntil/fingerprint/response/errorStatus를 가진다. 과거 단순 문자열/미지원 버전은 노출하지 않고 새 분석 대상으로 취급한다.
- 전체 공개 메타데이터, 선택한 본문의 전체 해시, 요청 스냅샷, 모델/정책 버전을 지문으로 사용한다. updated_at을 바꾸지 않은 본문 수정도 무효화한다. 정책 버전은 현재 `AiPortfolioAnalysisModel.version()`의 `portfolio-v1`이며 프롬프트 파일 자체는 자동 해시하지 않는다. 프롬프트/선택/분류 정책 변경 시 이 버전도 수동으로 갱신해야 한다. 삭제·비공개·추가·메타데이터 변경도 다시 비교한다.
- 공개 읽기는 짧은 REPEATABLE_READ 트랜잭션이다. `WHERE detailed_reason=이전값 또는 양쪽 NULL` 조건의 UPDATE가 정확히1행 성공한 요청만 PENDING 임대를 소유한다. JVM 로컬 락이 아니라 DB 비교·교환(CAS)이므로 인스턴스 사이에서도 같은 결과의 정상 동시 중복 실행을 막는다.
- 임대180초. 모델 실행은 DB 트랜잭션 밖, 전체 예산180초이며 각 호출 전 남은 예산과 Gemini 제한 시간(최대60초)을 검사한다. 예산을 넘기면 성공 결과를 저장하지 않는다. BFF 제한190초.
- 성공 시 권한·구독·자료 지문 재검증 후 자신의 PENDING 값과 일치할 때만 READY/NO_DATA로 바꾼다. 오래된 토큰은 새 결과를 덮어쓸 수 없다. 생성 중 권한 회수/자료 변경은 결과를 반환하지 않는다.
- 실패 시 해당 토큰의 PENDING만 FAILED로 변경하고 오류 상태를 유지한다. 부분 분석을 성공으로 저장하지 않는다. 실패 상태 저장 자체가 불가능하면 원래 오류를 반환하고 안전한 경고 로그만 기록한다. 프로세스 종료/저장소 장애로 남은 PENDING은 임대 만료 후 명시 POST로 회복 가능하다. 오래된 작업의 외부 호출 자체가 정확히 한 번이라는 보장은 없으며, 최종 결과 저장은 CAS로 보호한다.
- 자동 POST 재시도·자동 모델 교체·유료 전환·사용량 차감 없음. 2026-11-10 사용자 요청으로 완료 후30초/포커스 복귀 자동조회를 제거했다. 프론트는 PENDING에서만3초 간격으로 최대60회 GET하고 완료/자료없음/오류 시 중단한다. 다음 명시 요청에서 서버가 현재 권한/자료를 다시 검증한다. 계정/권한/결과 변경·닫기 시 요청 취소와 이전 응답 숨김, 브라우저 영구 저장 없음.

## 2026-11-10 사용자용 설명 표시

서버의 원래 응답과 평가 JSON은 보존한다. 화면은 UNKNOWN·자료부족 NO_DATA·UNKNOWN 질문·빈 평가 목록을 숨기며, 이 상세 표시 변경 자체가 후보를 제거하거나 점수 분모를 바꾸지는 않는다. 별도로 신규 기본 추천에는 위에서 연결한 관련성 필터를 적용한다. PARTIAL과 본문에 인용된 구현 중/미완성 내용, 명시적 차이는 남긴다.

검증된 근거만 출처 포트폴리오별로 묶어 개발자 이름·인용·요청과의 관계를 문장으로 표시한다. 동일 인용과 기술 목록은 합쳐 읽기 쉬운 문자열로 출력한다. 사용 근거 없는 자료는 추천 이유로 나열하지 않는다. 출처는 포트폴리오 제목 링크이며 기존 권한 검사를 거쳐 상세를 조회한다. 자료 선택 기준은 접어서 보여주고 미확인 요구 목록이 우회 노출되지 않도록 원래 긴 selectionReason은 화면에서 열거하지 않는다. 추가 모델 호출 없이 문장을 구성하며 작성자의 자기서술임을 유지한다.

PENDING에서만3초 간격으로 조회한다. 완료 뒤에는 포커스/visibility 이벤트와 정기 조회가 없다. 자동 새 분석/무한 재시도도 없다. 닫기/계정/권한/결과 변경 시 대기 타이머·요청을 취소하고 이전 응답을 숨긴다.

## 합성 포트폴리오

사용자의 별도 요청에 따라 `docs/sql/ai-portfolio-demo.sql`로 기존 데모 회원6명에 PUBLIC 합성 자료20개를 연결했다. 제목·요약·본문에 합성 자료를 표시한다. 실제 경력/성과로 제시하지 않는다. minjun6/premium3/member3/yuna3/seoyeon3/jiho2. 기존3개를 포함한 총23개 확인. 기존 행·회원·구독·스키마는 수정하지 않았다.

스크립트는 명시 실행 전용이며 동일 회원+제목으로 재실행 중복을 방지한다. 해당20개만 제거하는 `ai-portfolio-demo-cleanup.sql`은 제공하되 실행하지 않았다. 앱 시작 시 자동 삽입하지 않는다.

`premium@devmozip.demo`는 현재 PREMIUM이지만 구독 기록0건임을 실제 읽기 확인했다. 따라서 이 계정은6B에서403이다. 사용 가능한 계정은 현재 유효 구독과 역할을 모두 충족해야 하며, 구독 데이터 생성/정정은 해당 담당 범위다.

## 검증과 남은 범위

검증 명령·실행 수는 [진행 현황](ai-progress.md)의 최신6B 기록을 따른다. 6B HTTP/격리 H2 통합 테스트는 실제 서비스·저장·인증을 사용하지만 Gemini 응답은 가짜다. 모델 품질·공유 PostgreSQL의 신규 API/동시성·브라우저 수동 검증은 별도로 구분한다. 월 사용량·점수 가산·순위 변경·구독 도메인·PDF/첨부 분석은 구현하지 않는다.
